## 今日研究方向建议

1. **阅读 vLLM #40710 中 RMSNormGated+GroupedQuantFP8 融合内核的实现，评估其对 Qwen3-Next 等 GatedDeltaNet 模型在 ROCm 上的性能提升。** 该 PR 将延迟从 9us 降至 4.5us，端到端提升 1-3%。建议你重点阅读 `aiter/triton/rmsnorm_gated_quant_fp8.py` 中内核的融合逻辑，特别是如何将 reshape 操作合并到量化步骤中。然后，在本地 vLLM 环境中，使用一个 GatedDeltaNet 模型（如 Qwen3-Next），在 ROCm GPU 上对比启用/禁用该融合内核时的 prefill 和解码延迟，并记录在不同 batch size 下的加速比。

2. **跟进 SGLang #25181 中默认启用 FP8 权重矩阵乘法的变更，验证其对 MoE 模型 FP8 推理的吞吐影响。** 该 PR 将 `SGLANG_OPT_FP8_WO_A_GEMM` 设为默认启用，无需用户手动设置。建议你阅读该 PR 的代码变更，重点关注 FP8 GEMM 内核的调用路径和 fallback 逻辑。然后，在本地 SGLang 环境中，使用一个 MoE 模型（如 DeepSeek-V4），对比默认配置与手动禁用该优化时的解码吞吐和显存占用，并记录 FP8 GEMM 对连续批处理中不同专家激活数的性能表现。

3. **研究 TensorRT-LLM #14129 中为 DeepSeek V4 启用 MegaMoE 后端的实现，评估其对 MoE 推理中专家并行（EP）的优化效果。** 该 PR 添加了 MegaMoE 后端并增加了 CI 测试。建议你阅读该 PR 的代码变更，重点关注 MegaMoE 如何与现有的 TensorRT-LLM MoE 调度逻辑（如专家缓存、负载均衡）交互。然后，在本地 TensorRT-LLM 环境中，使用 DeepSeek V4 模型，对比启用/禁用 MegaMoE 后端时的解码吞吐和专家利用率，并记录该后端对 TP/EP 混合部署的兼容性。

4. **分析 FlashInfer #2944 中 CuTe DSL grouped-GEMM + combine 融合的实现，评估其对 Blackwell 上 MoE 推理的优化潜力。** 该 PR 在 Blackwell 掩码 GEMM 内核中增加了 grouped-GEMM + combine 融合，使 GEMM 后处理能直接加权散射归约到多 rank 输出缓冲区。建议你重点阅读 `cute_dsl/grouped_gemm_combine.cu` 中融合内核的实现，特别是如何将 GEMM 输出直接散射到多 rank 缓冲区。然后，在本地 FlashInfer 环境中，使用一个 MoE 模型，在 Blackwell GPU 上对比启用/禁用该融合时的专家计算延迟和通信开销，并评估其对端到端推理吞吐的提升。

5. **跟进 vLLM #39337 中 Model Runner v2 的 Oracle 机制，评估其对 Qwen3 等稠密模型推理性能的默认优化效果。** 该 PR 引入了一个“预言机”机制，默认对 Qwen3 等稠密模型启用 Model Runner v2，并允许通过环境变量强制选择版本。建议你阅读该 PR 的代码变更，重点关注 Oracle 如何判断模型类型并选择 runner 版本。然后，在本地 vLLM 环境中，使用 Qwen3 模型，对比 Model Runner v1 和 v2 在连续批处理中的解码吞吐和首 token 延迟，并记录 Oracle 自动选择对性能的默认优化效果。
