## 今日研究方向建议

1. **精读 vLLM Issue #38175（ViT Full CUDA Graph Tracker），把它作为你“多模态推理 + CUDA Graph 捕获边界”方向的直接切入点。** 该 RFC 指出当前仅解码器部分支持 CUDA Graph、ViT 编码器仍为 eager 执行，导致大量小内核启动开销——这正好命中你关注的多模态模型低精度/高效推理与 CUDA Graph 捕获。建议先读 issue 中关于 ViT 动态 shape（可变分辨率、patch 数）与 CUDA Graph 静态捕获冲突的讨论，确认 padding 策略与 graph 复用粒度的取舍；然后在本地 vLLM 中用 Qwen-VL 类模型对比 ViT eager 与 graph 捕获在 prefill 延迟、内核启动次数和显存占用上的差异，评估该路径对你多模态部署方案的收益。

2. **跟进 vLLM [PR #57104](https://github.com/vllm-project/vllm/pull/57104)（KVConnector + MTP 在 KV 压力下的死锁修复），把它作为你“分布式 KVCache + 投机解码”交叉场景的可靠性排查点。** 该修复针对生产部署 GLM5.2 时出现的调度器死锁，直接关联你关注的 KV Connector 分层缓存与 MTP 投机解码组合。建议阅读其死锁触发条件（KV 压力下 connector 回调与 MTP 调度器的锁顺序），确认修复是调整锁粒度还是引入超时回退；然后在本地 vLLM 中用 KVConnector + MTP 在显存压力场景下复现，对比修复前后在调度器存活、decode 吞吐和 KV 传输成功率上的差异，确认你的生产配置是否需要该补丁。

3. **精读 SGLang [PR #39671](https://github.com/sgl-project/sglang/pull/39671)（DeepSeek-V4.1 候选索引器库），把它作为你“稀疏/压缩 KV + 新硬件 kernel 适配”方向的布局参考。** 该 PR 实现两级候选索引器：首层对可达压缩位置打分并发布候选块，后续层仅在候选块内选择，且含 Hopper 与 Blackwell 双路径——正好命中你关注的 KV cache 压缩与 Blackwell 部署。建议阅读其候选块发布与后续层选择的索引结构，确认 Hopper 与 Blackwell 路径在数据布局上的差异；然后在本地 SGLang 中用 DeepSeek-V4.1 类模型对比候选索引器开启前后在 decode 延迟、索引开销占比和输出数值一致性上的表现，评估该方案对你压缩 KV 管理的借鉴价值。

4. **关注 NVIDIA Model-Optimizer [PR #2417](https://github.com/NVIDIA/Model-Optimizer/pull/2417)（Local Hessian NVFP4 权重量化尺度），把它作为你“FP4 低精度推理 + 量化误差控制”方向的实测入口。** 该文档给出按块输出误差目标的推导与 Qwen 系列实验结果，并附 hf_ptq.py 端到端复现命令，直接关联你关注的 FP4 量化与新硬件部署。建议阅读其 Local Hessian 尺度推导中按块误差目标的假设，确认与你在 Blackwell 上使用的 NVFP4 路径在 scale 布局上的差异；然后按文档复现 Qwen 系列量化，对比 Local Hessian 与默认 NVFP4 尺度在权重误差、下游任务精度和推理延迟上的差异，作为你 FP4 部署的量化基线。

5. **跟进 TensorRT-LLM [PR #16919](https://github.com/NVIDIA/TensorRT-LLM/pull/16919)（CuTeDSL MoE 中 DeepEP 元数据开销削减），把它作为你“MoE dispatch + 分布式推理”方向的性能优化参考。** 该 PR 在 CuTeDSL NVFP4 MoE 路径中引入 DeepEP 专家计数元数据直通，去除冗余排序与适配，并加入容量感知 tile 规划与回滚开关——直接命中你关注的 MoE dispatch 与 EP 分布式推理。建议阅读其元数据直通如何绕过冗余排序、容量感知 tile 规划在专家负载不均时的回退逻辑；然后在本地 TensorRT-LLM 中用 NVFP4 MoE 模型对比开启前后在 dispatch 延迟、专家负载均衡度和端到端吞吐上的差异，评估该优化对你 EP 部署路径的借鉴价值。
