## 今日研究方向建议

1. **跟进 vLLM [[Issue #60174](https://github.com/vllm-project/vllm/issues/60174)](https://github.com/vllm-project/vllm/issues/60174)（DFlash2/DSpark + prefix caching 在 Qwen3.8-27B NVFP4 上缓存命中后输出损坏）**，这是你"NVFP4 量化 + prefix caching + 投机采样"三条线交叉处今日最尖锐的实测缺口。建议先读 issue 中"0.29 正常、FP8 目标正常、MTP 正常，唯独 0.30/0.31 + NVFP4 + DFlash2 + prefix caching 组合崩"的对照矩阵，重点确认损坏是发生在 cache hit 后 KV 块的 scale 元数据未随块一起复用，还是 DFlash2 草稿模型在命中路径上读取了未反量化的 KV；然后在本地用 Qwen3.8-27B NVFP4 起 0.30 与 0.29 各一份，固定 prompt 前缀命中一次后逐 token 对比 logits，定位是 KV 数值偏差还是 draft 分支读错块。

2. **精读 vLLM [[[PR #56740](https://github.com/vllm-project/vllm/pull/56740)](https://github.com/vllm-project/vllm/pull/56740)](https://github.com/vllm-project/vllm/pull/56740)（ReLU2 激活的逐 token NVFP4 量化 MoE，集成 FlashInfer 融合内核）**，把它作为你"MoE dispatch + FP4 量化"方向的直接切入点。该 PR 在 Nemotron-3 上验证了精度，正好对应你关注的 W4A16/FP4 与 MoE 组合。建议先读其逐 token scale 的计算位置：确认 scale 是在 gate/up 投影后、ReLU2 之前算出，还是与 FlashInfer 融合内核的 dispatch 阶段交错；然后对照你已跟进的 [[Issue #60174](https://github.com/vllm-project/vllm/issues/60174)](https://github.com/vllm-project/vllm/issues/60174) 中 NVFP4 路径，判断两者是否共用同一套 per-token scale 布局——若共用，则 #60174 的缓存命中损坏可能同样波及 MoE 路径。

3. **跟进 vLLM [[Issue #59203](https://github.com/vllm-project/vllm/issues/59203)](https://github.com/vllm-project/vllm/issues/59203)（DeepSeek-V4.1-Flash 在 SM120 上因 FlashInfer 稀疏 MLA 解码内核只实例化 page_block_size=64 而无法启动）**，这是你"新硬件部署路径 + 稀疏 MLA + 分页 KV"方向今日最具体的落地阻塞。建议先读 issue 中确认的 kernel instantiation 列表，核对 pbs=32 缺失是模板未展开还是 SM120 编译期裁剪；然后在本地 SM120 上尝试用 pbs=64 的 kernel 配合 32 的块布局做一次手动重映射（或临时把 page_block_size 提到 64），观察是否只是索引 stride 不匹配、还是 MLA 稀疏模式本身依赖 pbs 对齐，从而判断这是纯实例化补齐还是需要改 kernel 逻辑。

4. **跟进 TensorRT-LLM [[[PR #19904](https://github.com/NVIDIA/TensorRT-LLM/pull/19904)](https://github.com/NVIDIA/TensorRT-LLM/pull/19904)](https://github.com/NVIDIA/TensorRT-LLM/pull/19904)（release/1.3 上按 NVIDIA 内核驱动版本门控 CFT，低版本回退 fence 调度）**，这是你"Blackwell/GB200 部署路径"方向今日最直接的硬件兼容性条目。建议先读 diff 中驱动版本判定（615+）与 CFT/fence 两条调度路径的分叉点，确认 CFT 依赖的是驱动提供的哪个同步原语；然后对照你本地 GB200 或 B300 环境的驱动版本，若低于 615 则验证回退路径下 continuous batching 的吞吐损失幅度
