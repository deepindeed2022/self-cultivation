## 今日研究方向建议

1. **跟进 TensorRT-LLM 中 `add + norm + fp8 quant` 融合 kernel 的实现，评估其对推理吞吐的影响**。今日 [NVIDIA/TensorRT-LLM [PR #12674](https://github.com/NVIDIA/TensorRT-LLM/pull/12674)] 融合了残差加法、RMSNorm 和 FP8 量化操作。这与你的“性能优化”和“量化（FP8）”方向直接相关。建议你阅读该 PR 的代码变更，重点关注融合 kernel 的 CUDA 实现细节（如如何避免中间显存读写）。然后，在 TensorRT-LLM 中，使用一个 FP8 量化模型（如 LLaMA-3-8B-FP8），对比启用/禁用该融合 kernel 时的解码吞吐和首 token 延迟。

2. **研究 vLLM 中 NVFP4 MOE 模拟 kernel 的变量名修复，评估其对 MoE 模型 FP4 推理正确性的影响**。今日 [vllm-project/vllm [PR #41630](https://github.com/vllm-project/vllm/pull/41630)] 修复了 `layer.weight` 到 `w13` 的拼写错误。这与你关注的“量化（FP4）”、“MoE dispatch”和“Blackwell 上 FP4 推理”高度相关。建议你阅读该 PR 的代码变更，定位 `w13_weight` 在 NVFP4 MOE 模拟 kernel 中的使用位置。然后，在 vLLM 中，使用一个 MoE 模型（如 Mixtral 8x7B），对比修复前后在 NVFP4 模拟模式下的输出 logits 一致性，验证该修复对推理正确性的影响。

3. **评估 llm-compressor 中 `propagate_error` 参数对量化后精度恢复的效果**。今日 [vllm-project/llm-compressor [PR #2008](https://github.com/vllm-project/llm-compressor/pull/2008)] 为顺序流水线添加了 `propagate_error` 参数，控制是否传播量化后的输出。这与你关注的“量化（W4A16/FP8）”方向直接相关。建议你阅读该 PR 的代码变更，重点关注 `propagate_error` 在顺序流水线中的传播路径（如如何影响后续层的量化误差）。然后，在 llm-compressor 中，使用一个 LLM（如 LLaMA-3-8B），对比启用/禁用 `propagate_error` 时，W4A16 量化模型在下游任务（如 MMLU）上的精度差异。

4. **跟进 SGLang 中最低 GPU 架构支持从 SM75 更新为 SM80 的动机，评估其对现有部署的影响**。今日 [sgl-project/sglang [PR #24336](https://github.com/sgl-project/sglang/pull/24336)] 将最低 GPU 架构支持从 SM75（图灵）更新为 SM80（安培）。这与你关注的“推理系统”和“新硬件上的优化方案”方向相关。建议你阅读该 PR 的讨论，重点关注为何放弃 SM75 支持（如性能瓶颈或代码维护成本）。然后，检查你现有的 SGLang 部署环境是否包含 SM75 架构的 GPU（如 T4），并评估升级到 SM80 后，在 A100 或 H100 上可能获得的性能提升。
