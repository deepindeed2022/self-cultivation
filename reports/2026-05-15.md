2. **跟进 SGLang #25379 中 FP4 路由 MoE 的显存优化实现，评估其对 MoE 模型 FP4 推理的显存节省效果。** 该 PR 通过复用前一层输出作为 `symm_output` 缓冲区，并提前释放 `attn_inputs` 张量，减少显存占用。建议你阅读该 PR 的代码变更，重点关注 `moe_fp4_kernel.cu` 中缓冲区复用的逻辑。然后，在本地 SGLang 环境中，使用一个 FP4 量化的 MoE 模型（如 Qwen3-30B 的 MXFP4 版本），对比启用/禁用该优化时的显存峰值和解码吞吐，记录显存节省比例。

3. **分析 vLLM #42685 中 FlashAttn 后端 fp8 kv-cache dtype 检查的修复，评估其对 FP8 推理中 KV 缓存稳定性的影响。** 该 PR 修复了 `supports_kv_cache_dtype()` 错误地接受未处理的 fp8 变体（如 fp8_e5m2）导致启动崩溃的问题。建议你阅读 `vllm/attention/backends/flash_attn.py` 中 dtype 检查的逻辑变更。然后，在本地 vLLM 环境中，使用一个 FP8 量化模型，尝试配置 `--kv-cache-dtype fp8_e5m2`，对比修复前后是否触发启动崩溃，并验证修复后系统是否正确回退或报错。

4. **研究 NVIDIA Model-Optimizer #1500 中 NVFP4 W4A16 权重量化特性移至 v0.45 的变更，评估其对 Blackwell 上 FP4 推理部署路径的影响。** 该 PR 将 NVFP4 W4A16 权重量化特性移至 v0.45 版本。建议你阅读该 PR 的代码变更，重点关注特性迁移后 API 的兼容性变化。然后，在本地 Model-Optimizer 环境中，使用一个 BERT 模型，尝试使用 v0.44 和 v0.45 版本分别进行 NVFP4 W4A16 量化，对比量化后的模型在 TensorRT-LLM 上的推理吞吐和显存占用，评估版本迁移对部署流程的影响。

5. **跟进 vLLM #41668 中 CUDA 12.9 wheel 构建切换到 manylinux_2_28 基础镜像的变更，评估其对 transformers 版本兼容性的影响。** 该 PR 将 CUDA 12.9 的 wheel 构建基础镜像切换到 PyTorch 的 manylinux_2_28 镜像，以匹配 PyTorch 的 glibc 版本要求。建议你阅读该 PR 的代码变更，重点关注 `Dockerfile` 中基础镜像的切换逻辑。然后，在本地 vLLM 环境中，使用 CUDA 12.9 和 PyTorch 2.8，对比该 PR 合并前后，使用最新 transformers 版本加载 Qwen3 等模型时是否出现 glibc 或 ABI 兼容性错误，并记录对模型加载成功率的提升。
