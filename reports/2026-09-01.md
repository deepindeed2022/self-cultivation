## 今日研究方向建议

1. **跟进 vLLM 今日 Kimi-K3 系列优化（#53524、#54781），将其作为你"MoE dispatch + 投机解码"方向的即时验证点。** 前者为 M=1 场景预取 ll_bf16 router 权重并启用专用内核，后者修复投机解码路径中 `active_non_spec_mask_cpu` 未初始化问题，两者均直接命中你关注的 MoE 调度与投机采样。建议你阅读 #53524 中 M=1 专用内核的调度逻辑，理解单 token 场景下如何通过预取减少 router 权重加载延迟。然后在本地 vLLM 中，用 Kimi-K3 或类似 MoE 模型对比"预取前后"在单 token 首延迟和吞吐上的差异，同时验证 #54781 修复对投机解码稳定性的保障。

2. **精读 TensorRT-LLM 今日 NVFP4 冷页 KV Cache 压缩（#18091），将其作为你"Blackwell 上 FP4 推理 + 分布式 KVCache"交叉点的架构级参考。** 该 PR 为 KV 缓存添加 NVFP4 冷页压缩方法，支持主机/磁盘分层并融合量化与传输，直接关联你关注的 FP4 推理与 KV Cache 优化。建议你阅读其冷页压缩与传输融合逻辑，理解如何在分层存储中平衡量化精度与带宽开销。然后在本地 TensorRT-LLM 中，用长上下文模型（如 Qwen3 或 DeepSeek）在 Blackwell 上对比"NVFP4 冷页压缩"与"FP8 冷页压缩"在显存占用、分层传输延迟和端到端吞吐上的差异，评估该方案对超长上下文部署的实际收益。

3. **关注 SGLang 今日 FlashInfer 滑动窗口长度 D2H 同步移除（#32218），将其作为你"分布式 KVCache 优化"方向的延迟优化参考。** 该提交避免滑动窗口长度的设备到主机同步，减少推理延迟，直接命中你关注的 KV Cache 管理与长上下文推理。建议你阅读其同步移除逻辑，理解如何在 FlashInfer 路径中通过异步处理避免 D2H 阻塞。然后在本地 SGLang 中，用支持 SWA 的混合架构模型对比"修复前"与"修复后"在滑动窗口场景下的端到端延迟和吞吐，重点关注该优化对长上下文多轮对话的实际收益。

4. **结合今日 tokenspeed Kimi-K3 MoE 投影合并优化（#1358）与 vLLM GPT-OSS FP8 MoE 权重加载修复（#54824），将其作为你"MoE 低精度推理"方向的 kernel 级验证点。** 前者将 router、routed latent 和共享 gate/up 投影合并为单个 GEMM 以减少内核启动，后者修复 QuarkW8A8Fp8MoEMethod 中丢失的 weight_dtype 导致 GPT-OSS FP8 权重加载失败。建议你阅读 #1358 的投影合并逻辑，理解如何通过 GEMM 融合减少 MoE 调度开销。然后在本地 vLLM 中，用 GPT-OSS 或类似 FP8 MoE 模型验证 #54824 修复后的权重加载正确性，并对比"合并投影"与"分离投影"在 kernel 启动次数和端到端吞吐上的差异。
