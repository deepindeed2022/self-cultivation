## 今日研究方向建议

1. **跟进 FlashInfer #4709 的 output-only KDA decode 内核，将其作为你"投机解码 + 混合架构推理"方向的 kernel 级验证点。** 该 PR 为 vLLM Kimi K3 循环验证提供即插即用替代，直接命中你关注的 speculative decoding 与 MoE 调度。建议你阅读其 KDA decode 内核实现，理解 output-only 模式下如何跳过不必要的循环状态计算。然后在本地 vLLM 中，用 Kimi K3 模型对比"默认验证路径"与"FlashInfer KDA 路径"在 decode 阶段延迟、显存占用和端到端吞吐上的差异，评估该内核是否值得集成到你的推理栈。

2. **精读 SGLang #37552 的量化重构第一步（FP4 marlin 死代码清理），将其作为你"Blackwell FP4 推理"方向的代码质量参考。** 该 PR 移除 MarlinConfig 和 MarlinLinearMethod 等无调用者代码并去重 FP4 marlin 辅助函数，直接关联你关注的 FP4 低精度推理路径。建议你阅读其去重逻辑，理解 FP4 marlin 辅助函数在 SGLang 中的调用链和冗余来源。然后在本地 SGLang 中，用支持 FP4 的模型（如 GLM-5.3 或 Qwen3）验证重构后 FP4 推理的正确性和性能无回退，同时评估该重构是否暴露了 FP4 路径中你尚未覆盖的 kernel 优化空间。

3. **关注 TensorRT-LLM #18278 的 FlashInfer JIT 工作区 MPI 隔离修复，将其作为你"分布式推理稳定性"方向的工程参考。** 该修复隔离 FlashInfer JIT 工作区避免多节点超时和初始化失败，直接命中你关注的分布式推理与多进程协作。建议你阅读其工作区隔离逻辑，理解 MPI 进程间如何避免 JIT 编译缓存冲突。然后在本地 TensorRT-LLM 中，用多节点场景（如 2×8 GPU）复现 FlashInfer 路径的初始化流程，对比"修复前"与"修复后"在多节点启动成功率、超时频率和端到端吞吐上的差异，评估该修复对大规模分布式部署的实际保障。

4. **结合今日 vLLM Issue #13941 的 72B 模型 8×A800 40G 唤醒 OOM，将其作为你"显存管理 + 大模型部署"方向的边界条件排查点。** 该问题报告了唤醒阶段 OOM，直接关联你关注的 KV Cache 管理与显存优化。建议你阅读 issue 中的环境信息和复现步骤，重点排查是唤醒时 KV Cache 预分配过大，还是 continuous batching 调度在唤醒场景下的显存碎片问题。然后在本地 vLLM 中，用 72B 模型在 8×A800 40G 上复现唤醒流程，对比"默认显存分配"与"手动限制 KV Cache 池"在唤醒成功率、OOM 频率和端到端吞吐上的差异，评估该问题是否影响你正在调研的分布式推理路径。
