2. **跟进 vLLM [[PR #57396](https://github.com/vllm-project/vllm/pull/57396)](https://github.com/vllm-project/vllm/pull/57396)（移除异构词表投机解码中的 CPU-GPU 同步），把它作为你"投机解码 + 异构词表"方向的调度优化参考。** 该改动让草稿模型 CUDA 内核可在目标模型执行期间异步入队，避免 CPU 启动速率成为瓶颈——直接关联你关注的 speculative decoding 与 continuous batching。建议先读其"目标模型与草稿模型执行阶段之间"的同步点分析，确认移除同步后草稿模型的 KV 写入与目标模型验证之间是否存在竞态（尤其是异构词表下 token id 映射的时序）；然后在本地 vLLM 中用 EAGLE3 或 MTP 跑异构词表场景，对比改动前后在 decode 吞吐、GPU 利用率和 accept rate 上的差异，判断该优化能否迁移到你当前的投机解码部署。

3. **精读 SGLang [[PR #40357](https://github.com/sgl-project/sglang/pull/40357)](https://github.com/sgl-project/sglang/pull/40357)（多模态调度器 padding 保留在 packed token 数组中），把它作为你"多模态推理 + 调度路径 CPU 开销"方向的优化参考。** 该改动用批量拷贝与 `frombuffer` 替代逐 token 序列遍历，避免 array 与 list 往返转换——正好命中你关注的多模态模型推理优化。建议先读其 packed token 数组的布局与 padding 保留策略，确认 `frombuffer` 路径对非连续内存或不同 dtype 的兼容性；然后在本地 SGLang 中用多模态模型跑一组变长图像输入，对比改动前后在调度器 CPU 时间、端到端 TTFT 和输出数值一致性上的差异，评估该模式能否迁移到你其他多模态调度路径。

4. **跟进 TensorRT-LLM [[PR #19375](https://github.com/NVIDIA/TensorRT-LLM/pull/19375)](https://github.com/NVIDIA/TensorRT-LLM/pull/19375)（按请求缓存 KV token 日志），把它作为你"disaggregated prefill/decode + prefix-caching 可观测性"方向的诊断工具。** 该功能通过环境变量开启后在 states 日志中输出每条请求的 `cached_kv_tokens_per_req`，直接关联你关注的 disaggregated 场景与 prefix-caching 命中排查。建议先读其日志输出点与 states 日志格式，确认 `cached_kv_tokens_per_req` 的统计口径（是 prefill 阶段命中还是 decode 阶段复用）；然后在本地 disaggregated 部署中开启该日志，用多轮对话压测对比不同 prefix 复用策略下的命中分布，定位你的 prefix-caching 是否存在命中率低于预期的情况。
