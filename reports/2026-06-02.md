## 今日研究方向建议

1. **跟进 vLLM #43332 中 FlashInferB12xExperts 对 W4A16 NVFP4 静态量化的支持，验证其对 MoE 模型量化兼容性的影响。** 该 PR 修复了量化检查，使 W4A16 (kNvfp4Static, None) 检查点正确路由到 FlashInfer 而非 Marlin。建议你阅读 `vllm/vllm/model_executor/layers/fused_moe/flash_infer_b12x_experts.py` 中 `supports_quantization` 方法的变更，重点关注 `activation_key` 为 None 时的处理逻辑。然后，在本地 vLLM 环境中，使用一个支持 W4A16 NVFP4 静态量化的 MoE 模型（如 Qwen3-MoE），对比修复前后在解码吞吐和量化路由正确性上的差异，验证该修复是否避免了因错误路由到 Marlin 导致的性能退化或崩溃。

2. **分析 NVIDIA/Model-Optimizer #1509 中流式隐状态数据集功能的实现，评估其对推理系统性能分析的实用价值。** 该 commit 新增了从运行中的 vLLM 服务实时获取每样本激活值的功能，替代磁盘存储。建议你阅读 `modelopt/torch/quantization/plugins/vllm/streaming_hidden_states.py` 中数据流管道的实现，重点关注如何从 vLLM 的 forward 钩子中捕获中间激活。然后，在本地 vLLM 环境中，使用一个大型模型（如 LLaMA-3-70B），启动 Model-Optimizer 的流式数据集，对比实时获取激活值与离线磁盘存储的开销差异，记录该功能对推理延迟和显存占用的影响，并评估其对 KV Cache 优化或量化校准的辅助价值。

3. **研究 vLLM #42187 中避免流水线并行气泡的优化，评估其对 PP 架构下解码吞吐的提升。** 该 PR 重新组织了 PP 调度和采样 token 的广播，以避免解码和分块预填充中的流水线气泡。建议你阅读 `vllm/vllm/worker/model_runner_v2.py` 中 PP 调度逻辑的变更，重点关注 `broadcast_tokens` 和 `schedule_pp` 函数的交互。然后，在本地 vLLM 环境中，使用一个支持 PP 的模型（如 LLaMA-3-70B），在 2 节点 8 卡配置下，对比启用/禁用该优化时的解码吞吐和首 token 延迟，记录 PP 气泡减少对端到端推理效率的提升，并评估其对连续批处理场景下调度复杂性的影响。

4. **跟进 SGLang #26966 中 Gemma 4 MTP 与 `trtllm_mha` 崩溃的修复，评估其对混合 SWA 模型推理稳定性的影响。** 该 PR 修复了在混合 SWA 模型（如 Gemma-4）上使用 `trtllm_mha` 和 FROZEN_KV MTP 时出现的 CUDA 非法内存访问崩溃。建议你阅读 `sglang/sglang/layers/attention/trtllm_mha.py` 中 MTP 相关内存访问逻辑的变更，重点关注 `frozen_kv` 模式下注意力掩码的边界检查。然后，在本地 SGLang 环境中，使用 Gemma-4 模型，配置 `trtllm_mha` + FROZEN_KV MTP，对比修复前后在长序列推理时的稳定性和解码吞吐，验证该修复是否消除了非法内存访问导致的崩溃，并评估其对混合 SWA 模型在推理框架中兼容性的提升。
