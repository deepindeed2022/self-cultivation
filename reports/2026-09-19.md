## 今日研究方向建议

1. **精读 vLLM Issue #54317（GLM-5.3-Flash 在 4xB200 上三个不相关内核的 CUDA illegal memory access），把它作为你“Blackwell 新硬件 + MoE/线性注意力内核”方向的可靠性排查入口。** 崩溃点同时落在 KDA 线性注意力、MHC TileLang 与 TRT-LLM fused MoE 三处，且 day-0 镜像即可复现——这正好命中你关注的 Blackwell 部署路径与 MoE dispatch。建议先读 issue 中三个内核的崩溃栈与复现脚本，确认是共享的 workspace/页表假设被破坏还是各自独立的越界；然后在本地 4xB200 上用相同 day-0 镜像跑一遍，对比单独禁用 KDA、单独禁用 fused MoE 时崩溃是否消失，定位是共性根因还是多 bug 叠加，再决定是否阻塞你当前的 GLM 系列部署。

2. **跟进 vLLM [[PR #57701](https://github.com/vllm-project/vllm/pull/57701)](https://github.com/vllm-project/vllm/pull/57701)（GLM-5 稀疏索引器 decode workspace 按池化序列长度定容，省 3072 MiB），把它作为你“稀疏/压缩 KV + 显存预算管理”方向的直接优化参考。** 该改动按池化序列长度重算 workspace，在默认 1M 模型长度下省下约 3 GiB 显存，直接关联你关注的 KV cache 显存管理与长上下文部署。建议阅读其 workspace 定容公式中对池化序列长度与 decode 批大小的依赖，确认它是否会在短序列小 batch 下过度分配；然后在本地 vLLM 中用 GLM-5 类模型对比改动前后在 1M 上下文下的峰值显存、decode 延迟和可支持的最大并发，评估该定容策略能否迁移到你其他稀疏注意力模型的 workspace 管理。

3. **精读 SGLang [[PR #39378](https://github.com/sgl-project/sglang/pull/39378)](https://github.com/sgl-project/sglang/pull/39378)（修复 GLM-5.2 在 disaggregated PP 下的 MTP），把它作为你“PD 分离 + PP + 投机解码”交叉场景的可靠性排查点。** 该修复涉及 PP 代理张量转发、embed_tokens 加载、DSA IndexShare 种子传递与 NIXL 映射多处，正好命中你关注的 disaggregated prefill/decode、TP/PP 与 MTP 投机解码。建议先读其 DSA IndexShare 种子在 PP 各 stage 间的传递路径，确认种子不一致是否会导致 MTP 草稿与目标模型索引错位；然后在本地 SGLang 中用 GLM-5.2 跑 disagg PP + MTP，对比修复前后在 accept rate、跨 stage 张量转发延迟和输出数值一致性上的差异，确认你的分离式部署是否需要该补丁。

4. **跟进 TensorRT-LLM [[PR #18389](https://github.com/NVIDIA/TensorRT-LLM/pull/18389)](https://github.com/NVIDIA/TensorRT-LLM/pull/18389)（默认输入处理器的前缀分词缓存），把它作为你“多轮对话省 token + prefix-caching”方向的直接实测入口。** 该改动在多轮 agent 场景复用最长前缀的分词结果、仅对尾部增量分词，把分词耗时从 43.7ms/请求降到 5.49ms，直接关联你关注的节约 tokens 的多轮对话方案与 prefix-caching。建议阅读其最长前缀匹配与缓存失效的判定逻辑，确认它与 KV prefix cache 的命中边界是否对齐（分词前缀命中但 KV 未命中时的行为）；然后在本地 TensorRT-LLM 中用多轮 agent 对话压测，对比开启前后在端到端延迟、分词耗时占比和前缀复用率上的差异，评估该优化能否与你现有的 KV prefix caching 叠加。
