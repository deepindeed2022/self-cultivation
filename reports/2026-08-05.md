## 今日研究方向建议

1. **跟进今日 llm-anthropic 0.26 中 Claude 5 系列新增的 WebSearch/WebFetch 服务端工具实现，评估其在 vLLM 中作为"工具调用感知的 prefix-caching"设计参考。** 该版本将工具执行下沉到服务端，直接关联你关注的多轮对话 token 节约与 prompt 优化。建议你阅读其服务端工具的事件流处理逻辑，理解工具结果如何作为结构化上下文注入。然后在本地 vLLM 中，使用 LLaMA-3-8B 模拟一个 5 轮"用户提问→工具检索→回答"的 agentic 场景，对比"工具结果作为独立 KV 段缓存"与"工具结果拼入用户 prompt 全量重算"在缓存命中率、首 token 延迟和总 token 消耗上的差异，重点关注工具结果复用对多轮成本的实际削减。

2. **分析今日 LLM 0.32 新增的 reasoning traces 支持，将其作为 speculative decoding 中"草稿模型推理链复用"的验证场景。** 该功能暴露模型内部推理轨迹，直接关联你关注的投机采样优化。建议你阅读其 reasoning 字段的序列化格式，思考：若草稿模型（如 1B）生成 reasoning trace 而目标模型（如 70B）仅验证最终答案，是否能减少目标模型的验证开销？可在本地 vLLM 中，使用 LLaMA-3-8B 作为草稿、LLaMA-3-70B 作为目标，对比"草稿生成完整推理链+目标验证"与"草稿仅生成 token+目标验证"在吞吐、接受率和端到端延迟上的差异，重点关注推理链复用对投机解码效率的实际影响。

3. **结合今日 LLM 0.32 的 smarter logging 特性，将其日志结构化思路迁移到 TensorRT-LLM 的 MoE dispatch 性能剖析中。** 该版本改进日志记录以支持更细粒度的调试，直接关联你关注的 MoE 分布式推理优化。建议你阅读其日志分级与上下文关联设计，然后在本地 TensorRT-LLM 中，使用 Mixtral-8x7B 配置 EP=2，为 all-to-all 通信和专家计算分别添加结构化日志（记录耗时、token 数、GPU 利用率），对比"结构化日志"与默认无日志在定位 dispatch 瓶颈（如通信等待 vs 计算饱和）的时间开销和可诊断性上的差异，重点关注该策略对 MoE 推理系统调优的实际价值。

4. **关注今日 llm-anthropic 0.26 对 Claude 5 的流式事件支持，将其作为 vLLM 中 disaggregated prefill/decode 阶段间数据传输的协议参考。** 该版本支持细粒度流式事件，直接关联你关注的 prefill/decode 分离架构。建议你阅读其事件类型划分（如 token 增量、工具调用、推理轨迹），思考：若在 vLLM 的 prefill 与 decode 节点间采用类似的事件流协议（而非完整 KV 传输），是否能降低跨节点通信开销？可在本地模拟一个 2 节点 prefill/decode 分离场景，对比"事件流式 KV 增量传输"与"整段 KV 一次性传输"在首 token 延迟、网络带宽占用和节点间同步开销上的差异，重点关注该策略对分布式推理中通信优化的实际效果。
