## 今日研究方向建议

1. **精读 vLLM Issue #29139 的 torch.compile 通信优化提案，将其作为你"MoE dispatch + 分布式推理"方向的 kernel 级参考。** 该提案通过 torch.compile pass 重写计算图，消除 TP MoE 下序列并行引入的冗余通信，直接命中你关注的 MoE 调度与 TP/EP 优化。建议你阅读其 pass 设计，重点理解如何在不修改线性层的前提下识别并去除 collectives。然后在本地 vLLM 中，用 MoE 模型（如 DeepSeek 或 Qwen3-MoE）在 TP=2/4 下对比"torch.compile pass 开启/关闭"在通信量、端到端吞吐和首 token 延迟上的差异，评估该方案对生产环境 MoE 推理的实用价值。

2. **跟进 vLLM #42545 的 Tensor Descriptor (TD) 采用 RFC，将其作为你"Triton kernel 开发 + 新硬件适配"方向的前瞻性调研点。** 该 RFC 提出用 TD 替代已弃用的 block_ptr，并利用 TMA 硬件加速，在 Intel Battlemage 上已有显著加速，直接关联你关注的 kernel 开发与硬件演进。建议你阅读 RFC 中的迁移策略，理解 TD 与 block_ptr 在内存访问模式上的差异及 TMA 的加速原理。然后在本地 Triton 中，选取你常用的一个 kernel（如 attention 或 MoE gate），用 TD 重写并对比"block_ptr 版本"与"TD 版本"在 Blackwell 或 Hopper 上的 kernel 延迟和显存带宽利用率，评估 TD 迁移的收益与工作量。

3. **关注 TensorRT-LLM #18213 的生成侧时间分解文档更新，将其作为你"分布式 KVCache + 性能 profiling"方向的调试工具参考。** 该 PR 补充了生成侧时间分解中缺失的 KV 传输段，使文档与代码一致，直接命中你关注的 KV cache 传输开销分析。建议你阅读其新增的三个时间分段定义，理解 KV 传输在生成阶段如何被独立度量。然后在本地 TensorRT-LLM 中，用长上下文模型在 TP=2 或 disaggregated 部署下运行 profiling，对比"更新前"与"更新后"的时间分解输出，验证 KV 传输开销是否被准确捕获，并据此优化你的跨节点 KV cache 传输策略。

4. **结合今日 SGLang #36848 的 HiCache 段锁协议替换与 #38718 的 Nemotron-H layer ID 传递修复，将其作为你"分布式 KVCache + 混合架构推理"方向的稳定性验证点。** 前者用段锁协议替代 skip_lock_node_ids，简化锁管理并避免错误释放；后者修复 Nemotron-H 在路由专家捕获时因缺 layer ID 导致的 CUDA graph 失败，两者均直接关联你关注的分布式缓存与混合架构。建议你阅读 #36848 的锁协议设计，理解段锁如何避免并发场景下的回执丢失。然后在本地 SGLang 中，用 Nemotron-H 或类似混合架构模型在 HiCache 开启下对比"段锁协议"与"旧方案"在并发请求下的缓存命中率、错误率和端到端延迟，评估该修复对生产环境多租户服务的必要性。
