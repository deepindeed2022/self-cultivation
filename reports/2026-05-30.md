1. **跟进 vLLM #44050 中 MRV2 可中断 CUDA 图支持，评估其对连续批处理场景下推理延迟的改善。** 该 PR 实现了 MRV2 的可中断 CUDA 图，直接关联你的 continuous batching 和推理系统优化方向。建议你阅读 `vllm/vllm/worker/model_runner_v2.py` 中可中断 CUDA 图的实现逻辑，重点关注中断点如何与调度器交互。然后，在本地 vLLM 环境中，使用 LLaMA-3-8B 模型，在连续批处理场景下对比启用/禁用可中断 CUDA 图时的解码吞吐和首 token 延迟，记录该特性在批大小动态变化时的性能表现。

2. **分析 NVIDIA/Model-Optimizer #1572 中强制 vLLM 非门控 MoE 通过 Triton 的修复，评估其对 MoE 量化兼容性的影响。** 该 PR 解决了 FlashInfer CUTLASS 后端隐藏中间激活导致量化失败的问题，直接关联你的 MoE dispatch 和量化优化方向。建议你阅读 `modelopt/torch/quantization/plugins/vllm/moe.py` 中 Triton 内核路由逻辑的变更，重点关注如何通过参数强制使用 Triton 内核。然后，在本地 vLLM 环境中，使用一个非门控 MoE 模型（如 Mixtral-8x7B），在启用 W4A16 量化时，对比使用 Triton 与 FlashInfer CUTLASS 后端的解码吞吐和量化成功率，验证该修复是否消除了量化插入失败的问题。

3. **研究 SGLang #24755 中大规模 add_constant 张量的向量化优化，评估其对推理系统性能的提升。** 该 PR 引入了架构感知的 16/32 字节向量化路径，直接关联你的 CUDA/Triton kernel 开发和性能优化方向。建议你阅读 `sglang/sglang/kernels/add_constant.cu` 中向量化路径的实现，重点关注不同架构下的向量宽度选择逻辑。然后，在本地 SGLang 环境中，使用一个需要频繁 add_constant 操作的模型（如带有大量偏置项的 BERT），对比启用/禁用向量化优化时的解码吞吐和显存带宽利用率，记录该优化在 Blackwell 上的加速效果。

4. **跟进 SGLang #23988 中自定义混合 SWA 模型识别的实现，评估其对混合注意力模型推理兼容性的影响。** 该 PR 允许通过 `hf_text_config` 中的 `is_hybrid_swa` 字段自动启用混合 SWA 内存路径，直接关联你的推理系统兼容性和 KV Cache 优化方向。建议你阅读 `sglang/sglang/layers/attention/hybrid_swa.py` 中模型识别逻辑的变更，重点关注 `hybrid_layer_pattern` 字段的解析和匹配规则。然后，在本地 SGLang 环境中，使用一个自定义混合 SWA 模型（如基于 LLaMA 修改的混合注意力版本），对比启用/禁用该识别逻辑时的解码吞吐和显存占用，验证是否无需硬编码白名单即可正确启用混合 SWA 路径。
