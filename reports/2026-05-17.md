1. **阅读 vLLM #42686 中 `torch.compile` 全图编译补丁的实现，评估其对 vLLM 推理性能的提升潜力。** 该补丁回传自 PyTorch 主分支，并通过 lm_eval 等基准测试验证。建议你阅读 `vllm/compilation/__init__.py` 中 `fullgraph` 参数的配置逻辑和补丁的触发条件。然后，在本地 vLLM 环境中，使用一个中等规模的 LLM（如 Qwen2.5-7B），对比启用/禁用 `torch.compile(fullgraph=True)` 时的 prefill 和解码延迟，并记录在不同 batch size 下的加速比，重点关注该补丁对连续批处理中 CUDA graph 捕获的兼容性。

2. **跟进 TensorRT-LLM #14069 中 Triton MOE 内存释放修复的代码，评估其对 MoE 模型推理稳定性的影响。** 该修复防止了未启用 swizzling 时意外释放存储，直接关联你的 MoE dispatch 和 Triton 内核开发方向。建议你阅读 `cpp/tensorrt_llm/kernels/triton_moe_kernel.cu` 中内存释放逻辑的变更，重点关注 `free_storage` 函数的条件判断。然后，在本地 TensorRT-LLM 环境中，使用一个 MoE 模型（如 Mixtral 8x7B），在未启用 swizzling 的配置下，对比修复前后是否出现显存损坏或推理输出不一致，并记录修复对解码吞吐的稳定性提升。

3. **分析 vLLM #42810 中 DeepSeek V4 在 ROCm 上的修复，评估其对 AMD 平台上 MoE 推理的兼容性影响。** 该 PR 移除了冗余归一化层、回退 torch 实现以避免 AITER 精度问题、修复 prefill topk 缓冲区逻辑。建议你阅读该 PR 的代码变更，重点关注 `vllm/model_executor/models/deepseek_v4.py` 中 topk 缓冲区逻辑的修复。然后，在本地 vLLM 环境中，使用 AMD GPU，对比修复前后 DeepSeek V4 的推理输出 logits 一致性，并记录修复对 prefill 阶段显存占用的影响，评估该修复对 ROCm 平台上 MoE 模型部署的稳定性提升。

4. **研究 SGLang #23760 中通过 AITER MoeRunner 统一 DeepEPMoE 和 MoriEPMoE 的变更，评估其对 MoE 推理中专家并行（EP）的优化效果。** 该 PR 通过 AITER MoeRunner 的 pre/post-permute 接口统一了两种 MoE 实现，废弃了 MoriEPMoE。建议你阅读该 PR 的代码变更，重点关注 `sglang/sglang/layers/moe_runner.py` 中统一接口的实现逻辑。然后，在本地 SGLang 环境中，使用一个 MoE 模型（如 DeepSeek-V4），对比统一前后在专家并行（EP）模式下的解码吞吐和通信开销，并记录该统一对模型加载和推理稳定性的影响。

5. **跟进 SGLang #24585 中统一基数缓存（带 hiCache）的 write_back 淘汰修复，评估其对 KV 缓存管理准确性的影响。** 该修复在淘汰叶子节点前备份祖先节点，并添加写入等待检查，直接关联你的 KV 缓存管理和 prefix-caching 方向。建议你阅读该 PR 的代码变更，重点关注 `sglang/sglang/kv_cache/radix_cache.py` 中 `write_back` 函数的逻辑变更。然后，在本地 SGLang 环境中，使用一个长序列模型，在启用 hiCache 的配置下，对比修复前后在连续批处理中的 KV 缓存命中率和推理输出一致性，并记录修复对显存碎片化的缓解效果。
