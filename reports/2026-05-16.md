## 今日研究方向建议

1. **阅读 vLLM #42689 中 MooncakeStoreConnector 磁盘级 KV 卸载的实现，评估其对 PD 分离部署中 KV 缓存管理的价值。** 该 PR 在 4×GB200 节点上验证了端到端性能，直接关联你的分布式推理和 Blackwell 硬件优化方向。建议你阅读 `vllm/distributed/connectors/mooncake_store.py` 中 `enable_offload` 和 `disk_gb` 参数的配置逻辑，以及 KV 缓存从 GPU 卸载到 SSD 的触发条件。然后，在本地 vLLM 环境中，使用一个长序列模型（如 DeepSeek-V4），在 PD 分离模式下，对比启用/禁用磁盘卸载时的 KV 缓存命中率和首 token 延迟，记录 SSD 卸载对显存压力的缓解效果。

2. **跟进 SGLang v0.5.12 发布中 DeepSeek V4 的全面推理支持，验证其对 MoE 模型在 Blackwell 上的部署路径。** 该版本集成了 HiSparse 卸载、预填充-解码分离、DeepGemm/FlashMLA 内核等多项你关注的特性。建议你阅读该版本的 Release Notes 和 `docs/cookbook/deepseek_v4.md`，重点关注 HiSparse 卸载的配置参数和预填充-解码分离的启动方式。然后，在本地 SGLang 环境中，使用 DeepSeek V4 模型，在 Blackwell GPU 上对比 v0.5.11 与 v0.5.12 的解码吞吐和显存占用，记录新版本对 MoE 专家并行（EP）的优化效果。

3. **分析 SGLang #25477 中 DeepSeek V4 HiCache 层数计算逻辑的修复，评估其对 KV 缓存卸载准确性的影响。** 该修复使 HiCache 的层数范围与实际模型层对齐，直接影响你关注的 KV 缓存管理。建议你阅读该 PR 的代码变更，重点关注 `HiCache` 中 `layer_count` 的计算方式如何从固定值改为动态推导。然后，在本地 SGLang 环境中，使用 DeepSeek V4 模型，对比修复前后在启用 HiCache 卸载时的推理输出 logits 一致性，验证修复是否消除了因层数错配导致的缓存损坏。

4. **研究 SGLang #25412 中 DSV4 cookbook 的 MegaMoE 开关和统一 Docker 镜像，评估其对 MoE 推理部署的简化效果。** 该 PR 添加了 MegaMoE 开关，并统一了 Docker 镜像，直接关联你的 MoE dispatch 和分布式推理方向。建议你阅读该 PR 的文档变更，重点关注 `MegaMoE` 开关的配置参数和统一 Docker 镜像的构建方式。然后，在本地 SGLang 环境中，使用 DeepSeek V4 模型，对比启用/禁用 MegaMoE 开关时的专家利用率和解码吞吐，记录统一镜像对部署流程的简化程度。

5. **评估 vLLM #42304 中实验性可中断 CUDA 图功能，分析其对 speculative decoding 中提前退出场景的性能影响。** 该功能允许在 CUDA 图执行过程中提前退出，直接关联你的 speculative decoding 和性能优化方向。建议你阅读该 PR 的代码变更，重点关注 `breakable_cuda_graph` 的实现机制和触发条件。然后，在本地 vLLM 环境中，使用一个支持 speculative decoding 的模型（如 Eagle），对比启用/禁用可中断 CUDA 图时的解码吞吐和首 token 延迟，记录该功能对投机解码中 draft 步骤的加速效果。
