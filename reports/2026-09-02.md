## 今日研究方向建议

1. **跟进 SGLang 今日 EAGLE draft-extend logits 剪枝优化（#35546），将其作为你"投机解码 + CUDA graph"方向的 kernel 级验证点。** 该 PR 在 draft-extend 阶段仅计算验证器所需行的 logits，减少计算和内存开销，直接命中你关注的 speculative decoding 与 CUDA graph 优化。建议你阅读其剪枝逻辑，理解在 CUDA graph 捕获下如何动态选择 logits 行而不破坏图重放。然后在本地 SGLang 中，用支持 EAGLE 的模型（如 Qwen3 或 Llama-3）对比"剪枝前"与"剪枝后"在 draft 阶段的计算量、显存占用和端到端吞吐上的差异，评估该优化对投机解码吞吐的实际收益。

2. **精读 FlashInfer 今日 moe_ep CUDA-graph 可捕获修复（#4795），将其作为你"MoE dispatch + 分布式推理"方向的稳定性参考。** 该 PR 修复了 moe_ep 分裂路径中 CUDA graph 捕获导致的重放崩溃问题，通过改变 handle 生命周期使其可捕获，直接关联你关注的 MoE dispatch 与 CUDA graph 兼容性。建议你阅读其 handle 生命周期管理逻辑，理解在 EP 分裂路径中如何避免 CUDA graph 重放时的资源冲突。然后在本地 FlashInfer 中，用 MoE 模型（如 DeepSeek 或 Kimi）在 EP 场景下对比"修复前"与"修复后"在 CUDA graph 捕获成功率、重放稳定性和端到端吞吐上的差异，评估该修复对大规模专家并行部署的实际保障。

3. **关注 TensorRT-LLM 今日 SM107 fused mHC split-K 优化（#18331），将其作为你"Blackwell 后续硬件推理路径"的早期验证点。** 该 PR 修复融合 mHC 内核 Phase-4 的 coherence 问题并支持不均匀 split-K，但仅限 SM107，直接命中你关注的 FP4/FP8 低精度推理与硬件演进。建议你阅读其 split-K 调度逻辑，理解不均匀 split-K 如何与 mHC 的 Phase-4 融合路径协同。然后在本地 TensorRT-LLM 中，用 BERT 或 Qwen 模型在 SM107 环境（若有）或通过模拟对比"均匀 split-K"与"不均匀 split-K"在 kernel 延迟、负载均衡和端到端吞吐上的差异，评估该优化对 Rubin 架构部署的预期收益。

4. **结合今日 llm-compressor GLM-5.3-Flash NVFP4 量化模型发布（#3110）与 FlashInfer SM107 设备门控放宽（#4755），将其作为你"Blackwell 上 FP4 推理 + 新模型部署"方向的验证点。** 前者为 GLM-5.3-Flash 提供 NVFP4 量化模型，后者允许 SM107 通过 attention-ts 设备检查，直接关联你关注的 FP4 推理与硬件兼容性。建议你阅读 llm-compressor 的量化 recipe，理解 GLM-5.3-Flash 的 NVFP4 量化超参与校准流程。然后在本地 vLLM 或 TensorRT-LLM 中，用 GLM-5.3-Flash 在 Blackwell 上对比"NVFP4 量化"与"FP8 量化"在模型精度、kernel 延迟和端到端吞吐上的差异，同时验证 FlashInfer 的 SM107 门控放宽对 attention 路径的实际影响。
