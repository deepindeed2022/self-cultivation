## 今日研究方向建议

1. **跟进 vLLM [[[PR #60345](https://github.com/vllm-project/vllm/pull/60345)](https://github.com/vllm-project/vllm/pull/60345)](https://github.com/vllm-project/vllm/pull/60345)（TokenSpeed MLA decode 的 minimum KV splits 配置）**，这是你"稀疏 MLA + KV Cache 管理 + decode 性能调优"三线交叉处今日最可直接落地的调参入口。建议先读 diff 中 `min_split_kv` 的默认值与约束条件，确认它是硬下限（低于则报错）还是软下限（低于则回退到自动切分）；然后在本地 DeepSeek 系 MLA 模型上固定 batch=1、context 从 4K 扫到 64K，对比 `min_split_kv` 取 1/2/4/8 时的 decode 尾延迟与 SM 占用，判断该配置在长 context 下是否因强制切分反而增加 reduce 开销。

2. **精读 SGLang [[[PR #42156](https://github.com/sgl-project/sglang/pull/42156)](https://github.com/sgl-project/sglang/pull/42156)](https://github.com/sgl-project/sglang/pull/42156)（DSv4.1 的 mxfp8 dispatch cache）**，把它作为你"MoE dispatch + FP8 量化"方向的直接切入点。该 PR 为 DSv4.1 引入 mxfp8 dispatch 缓存以减少重复分发开销，正好命中你关注的 MoE dispatch 与 FP8。建议先读缓存键的构造逻辑：确认缓存的是 token→expert 的映射结果还是 mxfp8 量化后的 scale 布局，以及缓存失效条件是否覆盖 batch 组成变化与 expert 并行度变化；然后对照你已跟进的 vLLM NVFP4 MoE 路径，判断 mxfp8 dispatch cache 的键设计能否迁移到 NVFP4 的 per-token scale 复用上。

3. **跟进 vLLM [[[PR #51207](https://github.com/vllm-project/vllm/pull/51207)](https://github.com/vllm-project/vllm/pull/51207)](https://github.com/vllm-project/vllm/pull/51207)（shm tensor arena 用于高效 CPU→GPU worker 广播）**，这是你"分布式推理 + TP 通信 + 新硬件部署"方向今日最具体的系统级优化。建议先读 `_reduce_tensor` 之上 arena 的写入方一次拷贝、读取方零拷贝共享槽位的实现，确认槽位生命周期与 TP 组内 rank 数、in-flight 广播次数的关系；然后在本地 TP=4/8 配置下，对比启用 arena 前后 CPU→GPU 广播的 H2D 拷贝量与端到端 prefill 延迟，判断收益是否随 TP 增大而放大，并顺带核对今日 [[[PR #60724](https://github.com/vllm-project/vllm/pull/60724)](https://github.com/vllm-project/vllm/pull/60724)](https://github.com/vllm-project/vllm/pull/60724)（融合 mHC 残差检查放宽一个 bf16 ulp）是否说明该广播路径在 ROCm 上存在数值一致性差异。

4. **精读 Triton [[[PR #12213](https://github.com/triton-lang/triton/pull/12213)](https://github.com/triton-lang/triton/pull/12213)](https://github.com/triton-lang/triton/pull/12213)（triton_kernels 支持 Blackwell 四列激活缩放对齐）**，把它作为你"Blackwell 上 FP8/FP4 推理 + Triton kernel 开发"方向的直接切入点。该 PR 将 Blackwell 激活缩放从八列填充改为四列对齐以减少存储浪费，正好命中你关注的 Blackwell 部署路径与低精度推理。建议先读对齐逻辑中四列与八列的分支条件：确认是依据 `sm_version` 还是依据 scale 张量的实际列数判断，以及四列对齐后 MMA 指令的 K 维是否仍满足硬件要求；然后在本地 Blackwell 上用 BERT 类模型跑 FP8 推理，对比四列与八列对齐下的 kernel 吞吐与显存占用，判断该改动对非 MoE 的 dense 模型是否
