## 今日研究方向建议

1. **精读 TensorRT-LLM #18075 的 cuDNN attention 后端，将其作为你"Blackwell 新硬件注意力后端选型"方向的对照实验起点。** 该 PR 新增支持非量化/FP8/MXFP8 的 cuDNN attention 后端，并带图缓存、掩码与 LSE 输出，直接命中你关注的 FP8 低精度推理与新硬件部署路径。建议先读其 backend 注册与 graph cache 复用逻辑，确认它与你现有 TRT-LLM 内置 attention 插件在 mask 与 LSE 语义上的差异；然后在本地用同一模型（如 Qwen 或 DeepSeek）在 Blackwell 上对比 cuDNN 后端与现有后端在 prefill/decode 延迟、显存占用和 LSE 数值一致性上的表现，判断是否值得纳入你的推理栈。

2. **跟进 FlashInfer #4985 的 DeepSeek MoE 对比基准，将其作为你"MoE dispatch + FP4 低比特推理"方向的量化收益标尺。** 该基准新增 BF16 与 NVFP4 两种精度模式，直接对比 CuTe DSL 低比特 MoE 与纯 TRTLLM BF16，正好命中你关注的 MoE dispatch 与 FP4 推理。建议阅读其 benchmark 脚本中 NVFP4 权重布局与 scale 处理方式，确认与你在 TensorRT-LLM 中使用的 NVFP4 路径是否一致；然后在本地复现该基准，重点对比 BF16 与 NVFP4 在 decode 阶段每 token 延迟和专家路由开销上的差距，作为你评估 FP4 MoE 部署收益的基线。

3. **关注 SGLang #38558 的大批次 MTP 短卷积元数据扩展，将其作为你"投机解码 + CUDA graph 捕获稳定性"方向的边界条件排查点。** 该 PR 通过减半 token tile 支持超过 1023 请求的 MTP 大批次，避免 CUDA graph 捕获失败，直接关联你关注的 speculative decoding 与 continuous batching。建议阅读其 token tile 切分逻辑，理解短卷积元数据在 MTP 场景下如何随 batch 规模增长而溢出；然后在本地 SGLang 中用 MTP 模型压测 batch size 从 512 到 2048 的区间，对比修复前后 CUDA graph 捕获成功率与端到端吞吐，确认你生产环境的 batch 上限是否需要相应调整。

4. **精读 SGLang #38855 的 FP8 缓存前缀反量化修复，将其作为你"分布式 KVCache + FP8 低精度推理"方向的正确性验证点。** 该修复处理稀疏 prefill 内核中对 FP8 缓存前缀的反量化，直接命中你关注的 KV cache 低精度存储与 prefix-caching。建议阅读其反量化在稀疏 prefill 路径中的插入位置，确认 FP8 前缀在 radix 缓存命中后是否会被正确还原为计算精度；然后在本地 SGLang 中用长上下文模型开启 FP8 KV cache 与 prefix caching，对比修复前后在缓存命中场景下的输出正确性和 prefill 延迟，评估该修复对你多轮对话 KV 复用方案的影响。

5. **结合 tokenspeed #1486 的 AMD GLM-5.3 FP8 dense prefill 优化与 #1485 的小路由专家屏障移除，将其作为你"FP8 prefill 优化 + MoE 调度"方向的跨平台参考。** 前者通过专用形状注册与归约策略优化降低 TTFT，后者移除小路由专家块的全局内存屏障，两者分别关联你关注的 FP8 推理与 MoE dispatch。建议阅读 #1486 中大 prefill 网格下的归约策略设计，理解其如何减少跨 SM 同步开销；同时对比 #1485 的屏障移除思路，评估在 NVIDIA 平台上是否存在类似的小路由专家同步瓶颈，可在你的 MoE 推理路径中做一次 profiling 验证。
